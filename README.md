# aiapps

Small self-hosted apps published to GitHub Pages under `/aiapps/<name>/`,
plus a landing page at the site root listing all of them.

Currently:

- **[Flight Price Tracker — DFW ⇄ ORD](#flight-price-tracker--dfw--ord)**
  at `/aiapps/flight-price-tracker/`
- **tmux Cheat Sheet** at `/aiapps/tmux-cheatsheet/`

## Site structure

- `docs/index.html` — landing page, generated by `scripts/build_apps_index.py`.
- `docs/aiapps/<slug>/index.html` — one folder per app. GitHub Pages
  (served from `docs/` on the default branch) turns each folder into
  `https://<user>.github.io/<repo>/aiapps/<slug>/`.
- `apps/*.html` — source for **static** apps (self-contained HTML files
  you author directly, e.g. `apps/tmux-cheatsheet.html`). To publish a
  new one: drop the file in `apps/`, add an entry to `STATIC_APPS` in
  `scripts/build_apps_index.py`, and push — `publish-site.yml` republishes
  automatically.
- Apps with dynamic/generated content (like the flight tracker) write
  straight to `docs/aiapps/<slug>/index.html` from their own script
  (`scripts/build_site.py`) and are listed in `GENERATED_APPS` in
  `scripts/build_apps_index.py` just so the landing page can link to them.

## Flight Price Tracker — DFW ⇄ ORD

Checks the round-trip economy price for the next upcoming Friday → Sunday
weekend flying Dallas/Fort Worth (DFW) ⇄ Chicago O'Hare (ORD), publishes
the history to the Pages site, and posts a GitHub Issue update (which
triggers your normal GitHub notifications/email) with every check.

- `.github/workflows/flight-price-tracker.yml` runs daily on a schedule
  (`workflow_dispatch` also enabled for manual runs).
- `scripts/check_flight_price.py` computes the nearest upcoming Friday and
  Sunday, queries Google Flights (via the [`fast-flights`](https://pypi.org/project/fast-flights/)
  library — no API key required), and appends the result to
  `data/history.json`.
- `scripts/build_site.py` renders `data/history.json` into
  `docs/aiapps/flight-price-tracker/index.html` (a price chart + full
  history table).
- The workflow commits the updated data/site back to the branch, then
  creates/updates a GitHub Issue titled **"✈️ DFW ⇄ ORD Weekend Flight
  Price Tracker"** and adds a comment with the latest result — this is
  what generates your GitHub notification/email.

### Fixed: weekend date bug (2026-09-23)

`next_weekend()` used to keep re-querying *this* weekend's Friday even
after it had already passed (i.e. on Saturday/Sunday), which Google
Flights correctly rejected as "no flights found" since that departure
date was in the past. It now always rolls forward to the next Friday
that hasn't passed yet — see `scripts/check_flight_price.py`.

## One-time setup checklist

1. **Fix the default branch.** GitHub repo settings currently list
   `claude/flight-price-github-action-qk2xi8` as the **default branch**,
   not `main` — that's why the scheduled workflow has been running off
   that branch instead of `main`, and it's also why the tmux cheat sheet
   you uploaded straight to `main` wasn't picked up by any workflow.
   Go to Settings → General → Default branch → switch to `main`, merge
   this branch into `main` one more time, and going forward only push to
   `main` (or update the `branches:` list in `publish-site.yml` /
   `flight-price-tracker.yml` if you want to keep using another branch).
2. **Enable GitHub Pages:** repo Settings → Pages → Source: "Deploy from a
   branch" → Branch: `main`, folder: `/docs` → Save. Site root:
   `https://<your-username>.github.io/<repo>/`. **This has never been
   turned on** (`has_pages` is currently `false`), which is why the page
   wasn't loading — it's not a bug in the site itself.
3. **⚠️ Private repo caveat:** this repository is **private**. GitHub
   Pages for private repos requires a GitHub Pro/Team/Enterprise plan —
   on the free plan, Pages won't publish even after step 2. Either make
   the repo public, upgrade your plan, or skip Pages and view
   `docs/aiapps/.../index.html` directly from the repo instead of a live
   URL.
4. **Notifications:** make sure "Issues" notifications are enabled for
   this repo under your GitHub notification settings (Watch the repo).
   The workflow creates the issue once and comments on it daily.

## Adjusting things

- **Airports:** change `FROM_AIRPORT` / `TO_AIRPORT` in
  `scripts/check_flight_price.py`.
- **Schedule:** edit the `cron` line in `flight-price-tracker.yml`
  (currently `0 13 * * *`, i.e. daily at 13:00 UTC / ~8am Central).
- **How far ahead it looks:** `next_weekend()` always targets the
  *closest* upcoming Fri→Sun weekend. To track multiple weekends at once,
  that function and the fetch loop would need to loop over several
  weekends.
- **Adding another app:** see "Site structure" above.

## Known limitations

- `fast-flights` works by parsing Google Flights' public search page —
  there's no official free API for this. Google occasionally
  rate-limits or blocks automated requests, especially from shared
  cloud/datacenter IP ranges like GitHub Actions runners. The script
  retries a few times on failure, and failed checks are still recorded
  (visible on the Pages site and in the issue) rather than failing
  silently. If checks start failing consistently, this is the most
  likely cause.
- Price shown is for 1 adult, economy, and reflects whatever Google
  Flights returns as the top-priced result set at query time — it's a
  spot check, not a guaranteed bookable fare.

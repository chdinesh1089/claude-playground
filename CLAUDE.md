# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Keeping this file current (required)

Update this file in the **same commit** as any change to apps, scripts,
workflows, or conventions: fix any section the change makes stale and add
a line to the Changelog at the bottom. A project hook
(`.claude/hooks/require-claude-md.sh`, wired in `.claude/settings.json`)
blocks `git commit` when the staged files include anything other than
bot-generated output (`data/`, root `index.html`,
`aiapps/flight-price-tracker/index.html`) and `CLAUDE.md` is not staged.

## What this repo is

A small static site served by GitHub Pages at
`https://chdinesh1089.github.io/claude-playground/`. Each app is one
self-contained HTML file at `aiapps/<slug>/index.html` →
`/aiapps/<slug>/`. There is no build system, package.json or test suite.
The only generated files are the landing page and the flight tracker page,
and both are built by Python scripts that use only the standard library.

| Path | What | Source |
|---|---|---|
| `index.html` | Landing page listing every app | generated by `scripts/build_apps_index.py` |
| `aiapps/flight-price-tracker/` | DFW ⇄ ORD weekend fare history | generated by `scripts/build_site.py` from `data/history.json` |
| `aiapps/tmux-cheatsheet/` | tmux cheat sheet (uploaded by the user) | static |
| `aiapps/paper-plane/` | *The Paper Plane*, 71 s three.js story | static |
| `aiapps/flappy-3d/` | *Flap 3D*, a three.js flappy-bird-style game | static |
| `aiapps/lib/three-bundle.min.js` | Shared three.js r186 + add-ons bundle | built manually (see below) |

## Branches and deploy

- Pages serves the **root of `main`**. `.nojekyll` makes Pages serve files
  exactly as committed (no Jekyll processing). A leftover `docs/` or
  `apps/` folder would not be served, so don't add them.
- Work happens on `claude/flight-price-github-action-qk2xi8`. To ship, check
  that main can fast-forward and push the branch head to it:
  `git fetch origin main && git merge-base --is-ancestor origin/main HEAD && git push origin HEAD:main`.
  If the check fails, merge `origin/main` first (the daily bot commits data to main).
- `.github/workflows/flight-price-tracker.yml` runs daily (cron `0 13 * * *`,
  often hours late) and on manual dispatch. It fetches the price, rebuilds
  both generated pages, commits to main, then creates or updates issue #1
  (label `flight-price-tracker`) and adds a comment, which is how the user gets
  notified.
- `.github/workflows/publish-site.yml` runs on pushes to main that touch
  `aiapps/**` or the two build scripts. It regenerates the landing page and
  tracker page and commits them if they changed. Commits made with
  GITHUB_TOKEN don't trigger other workflows, so the two can't loop.
- Both generators are **deterministic** (no build timestamps). Keep them
  that way, or every run makes a useless commit.

## Commands

```bash
pip install -r requirements.txt          # fast-flights (only the price check needs it)
python3 scripts/check_flight_price.py    # live Google Flights query; appends to data/history.json
python3 scripts/build_site.py            # -> aiapps/flight-price-tracker/index.html
python3 scripts/build_apps_index.py      # -> index.html (lists every aiapps/*/index.html)

# Serve locally under the same /claude-playground/ prefix Pages uses
mkdir -p /tmp/site && ln -sfn "$PWD" /tmp/site/claude-playground && python3 -m http.server -d /tmp/site 8000
```

Testing is headless Playwright against a local server. Playwright is installed
globally at `/opt/node22/lib/node_modules/playwright`; require it by that path
and don't run `playwright install`. WebGL needs
`chromium.launch({ args: ['--use-angle=swiftshader', '--enable-unsafe-swiftshader', '--autoplay-policy=no-user-gesture-required'] })`.
SwiftShader is slow, so the adaptive DPR will drop. That's expected and
doesn't count as a regression. Test hooks:
- Paper Plane: `window.story`, with `.seek(t)`, `.t` and `.dpr`.
- Flap 3D: `window.game`, with `state` (`ready|playing|dying|over`), `score`,
  `birdY`, `vy`, `paused`, `dpr`, `best`, `muted`, `nextGap()` and `setScore(n)`
  (use it to screenshot each time of day).
A simple bot that presses Space whenever `birdY` drops below `nextGap().y`
should score several points.

The sandbox can't reach `*.github.io` or Google Flights. Verify a deploy
through the GitHub MCP tools (Actions runs, `pages-build-deployment`), not
with curl.

Rebuilding the three bundle (only needed to upgrade three.js or add an
add-on): make an `entry.js` that does `export * from 'three'` and re-exports
`Sky`, `EffectComposer`, `RenderPass`, `UnrealBloomPass`, `OutputPass`,
`ShaderPass` and `mergeGeometries` from `three/addons/...`. Then run
`npx esbuild entry.js --bundle --format=esm --minify --outfile=aiapps/lib/three-bundle.min.js`.
Apps load it with an import map: `{"imports":{"three":"../lib/three-bundle.min.js"}}`.
Don't use a CDN.

## Flight tracker

- `check_flight_price.py` works out the next Friday that hasn't passed
  (`days_ahead = (4 - weekday) % 7`; a Friday counts as its own weekend, and
  Sat/Sun roll over to the next week). It queries Fri DFW→ORD / Sun ORD→DFW
  round trips with fast-flights 3.1
  (`create_query(flights=[FlightQuery…], trip='round-trip', …)` then
  `get_flights(q)`) and makes up to 3 attempts, 15 s apart.
- For round trips, Google returns **outbound legs only**. `price` is the
  cheapest full round trip, and `outbound_stops = len(best.flights) - 1`
  describes the Friday flight only. Older records use `segments` (the
  outbound leg count) instead; `build_site.py` converts them.
- A record in `data/history.json` (capped at 1000) looks like
  `{checked_at, weekend_start, weekend_end, from_airport, to_airport, currency, status, price, airlines, outbound_stops}`.
  On failure, `status` isn't `ok` and the record includes an error. Failures
  are recorded and reported, never silently skipped.
  `data/latest_summary.json` is the same record plus `trend`, and the
  workflow's issue comment reads it.
- To change airports, edit `FROM_AIRPORT`/`TO_AIRPORT` in
  `check_flight_price.py` and the labels in `build_site.py`.

## Landing page

`build_apps_index.py` finds every `aiapps/*/index.html` and lists it using
the page's `<title>` and `<meta name="description">`. To add an app, add
the file; nothing needs registering. A folder without an `index.html`
(such as `aiapps/lib/`) isn't listed.

## 3D app conventions (Paper Plane, Flap 3D)

Both apps share one rendering pipeline. Copy these patterns rather than
reinventing them:
- ACES tone mapping; `PCFShadowMap` with `shadow.radius`
  (`PCFSoftShadowMap` was removed in r186).
- `EffectComposer` with RenderPass, UnrealBloomPass and OutputPass on an MSAA
  half-float target.
- `THREE.Sky`, plus an overlay dome for storm and night skies and a
  starfield. The environment is keyframed through `sampleEnv()` and blended
  with `smoother`.
- Image-based lighting comes from a PMREM capture of the sky. **Set
  `showSunDisc = 0` during the capture**, or the scene blows out.
- Adaptive DPR: step down when the average frame time is over 21 ms, and step
  back up after 5 good checks. **Flap 3D measures only during active play.**
- Shaders compile behind the title or start card to avoid first-frame hitches.
- Clouds are point sprites with a per-point `aSize`, injected via
  `onBeforeCompile`. Unlit HDR materials need `fog: false` and a brightness
  multiplier, or they turn grey.
- Everything is procedural (no model or image files). Respect
  `prefers-reduced-motion`. Keyboard shortcuts must keep working after a
  button is clicked, so blur buttons or don't let them keep focus.

**Paper Plane:** the whole scene is a pure function of the timeline value `t`,
which is what makes scrubbing and `seek` work. Never keep state that
depends on what happened in earlier frames. The flight path is a clamped C2
cubic spline in time, and the bank angle comes from the lateral acceleration.
Keys: Space, ←/→, R.

**Flap 3D:**
- Physics runs at a fixed 120 Hz with an accumulator and interpolated
  rendering.
- Constants: `G=-30`, `FLAP=9.5`, `VMAX=-16`, `BIRD_R=0.44`, `SPACING=7.5`,
  6 pooled pipe pairs.
- Difficulty: speed is `min(10, 6+0.08*score)` and the gap is
  `max(3.4, 4.2-0.02*score)`. From score 15, one pipe in three slides.
- Time of day follows `score/10` through the sky keyframes. A light on the
  bird keeps it visible at night.
- Portrait screens pull the camera back (`camDist` formula).
- `localStorage` keys: `flap3d:best` and `flap3d:muted`, always accessed inside
  try/catch.
- Sound is synthesized with WebAudio (no audio files).
